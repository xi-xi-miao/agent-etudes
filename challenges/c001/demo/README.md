`demo-6.json` is a hand-authored 6-part tier-2 instance (strip width 200): two 100x100 L-shapes with a 50x50 notch, a 50x50 square, a 60/60 right triangle, a trapezoid and a 30x30 square.
`baseline.svg` is `tools/baseline.py` on it — bounding-box shelf packing, three columns, used length 190, utilization 59.5% — and `improved.svg` is the hand-written `demo-6.improved.json`, where the two L-shapes interlock so their notches coincide, the 50x50 square drops into that shared notch, and the triangle is rotated 315 degrees to nest in the leftover column: used length 150, utilization 75.3%.
The two SVGs and `demo-6.baseline.json` are generated by `bash challenges/c001/demo.sh` rather than drawn by hand, but they are kept in the tree: the challenge README embeds them as `![…](demo/baseline.svg)`, so a missing file is a broken image. Re-run the script after any change to `baseline.py` or `render.py` — `tests/test_demo.py` fails if the committed pair goes stale. The hand-authored inputs are `demo-6.json` and `demo-6.improved.json`.
The point of the pair is that better layouts are legible as pictures: same six parts, visibly less whitespace, one number to say so.
